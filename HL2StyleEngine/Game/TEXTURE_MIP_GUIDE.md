## Try It

Run `LaunchTextureMipTest.bat` from the repository root. It builds Release, prepares the existing immutable atmosphere asset snapshot, and opens a separate gallery of 25 distinct project models. Preparation can take time and warms file caches; this launcher is not a cold-loading benchmark. The gallery is generated by the test module, not a new editable level JSON.

- WASD moves; Q/E moves vertically; hold right mouse to look.
- The Texture Residency panel controls the texture-payload target, initially 24 MiB.
- Full resolution reference pins every model at full detail for comparison. Uncheck it to resume distance/budget selection.
- Nearby models remain full detail. Distant ones can use mip tails, with hysteresis to reduce repeated boundary changes.
- The panel distinguishes actual resident texture payload from conservative per-model estimates. Shared textures make those estimates larger than actual usage.

This gallery has no gameplay physics or flashlight. Continue using the existing gameplay launchers for those systems. No importer action or source-asset replacement is needed.

## Implementation Contract

`TextureCooker.TryReadMipTail` seeks past unused higher-detail payloads in the existing version-1 BC7/BC5/LZ4 cache. It checks headers and record lengths across the file and decompresses/checksums every requested mip. Skipped payload checksums are checked when those mips are requested, not during a coarse request. Ordinary `TryRead` requests every mip and retains full validation. No new disk format or recook is required.

`AssetPackage.LoadMipTail` is explicit; ordinary `Load` remains full detail. Texture GPU identities include the first resident mip, preventing full/coarse resources from aliasing. Unsupported, changed or corrupt package data retains the strict-source fallback. A fallback may decode the full source before taking its mip tail, so this is not a hard CPU-memory/I/O bound.

`MipModelResidency` prepares on a worker, uploads under existing render-thread budgeting, and publishes only after all parts are ready. The previous visible model stays until replacement; old GPU resources retire through frame fences. Failure retains the current model, retry is explicit, and superseded successes or failures cannot overwrite/block the latest request. Callers own render-thread access and admission control; the gallery admits one replacement at a time and waits for retirement before admitting another.

`MipResidencyBudget` chooses desired mip levels from conservative per-model texture costs. Pins are not degraded to hide an impossible target; over-budget pins are reported. This is **not a hard total RAM/VRAM cap**: temporary old/new overlap, duplicated geometry, driver allocations, fallback RGBA expansion and other renderer resources are outside this target. Shader/UI/lighting quality is not changed to meet it.

The prototype replaces whole model render resources, not individual texture bindings. It needs texture-granularity replacement, projected-size/UV-aware demand, room prefetch and visual transition acceptance before gameplay integration. Distance-only demand can show detail changes and is not suitable for all asset scales. A reduced `PreparedTexture` cannot reconstruct discarded mips; promotion reloads the package at the requested detail.

## Validation

Release, local RTX 3060 / D3D11, sequential normal-desktop runs:

- 483 CPU checks pass across 33 models and 70 unique textures, including exact selected mip bytes, geometry/material identities, pinning/hysteresis, corrupt resident/skipped payloads, truncation and clock telemetry.
- Requesting mip 3 for all test textures reduces decoded mip bytes **96,607,472 -> 1,511,408**, and compressed payload bytes read **53,948,336 -> 1,008,111**. These exclude headers, OS read-ahead, geometry and other resources; they are not whole-game memory or load-time savings.
- GPU tests pass: restored full detail matches the reference within 1/255; eight repeated promotion/demotion cycles return to the same resident bytes; failed replacements retain their model; retry and superseded success/failure work; retirement releases all owned texture bytes. Crate texture payload: **136,656 full / 2,256 coarse bytes**.
- The initial 3,600-sample gallery soak completes 138 replacements across 25 models with zero package fallbacks: **16.661 ms mean / 18.662 ms P95**, zero frames above 33.3 ms; peak **23.44 MiB**, last settled **9.64 MiB** texture payload. Report: authoring `qa/mip-lab-20261027-110131.json`. This is a gallery-only workload, not full-game performance acceptance.
- Final repeat with explicit frame-time and positive-settled-memory gates passes: **16.661/17.372 ms** mean/P95, all 3,600 samples, 138 replacements, zero >33.3 ms or fallbacks and identical peak/settled bytes. Report: `qa/mip-lab-20261027-111946.json`. Both runs finish with zero owned texture bytes after retirement.
- The actual BAT opens correctly; textured models are visible. Manual full-detail comparison shows **74.80 MiB** resident versus **9.64 MiB** budgeted at the starting view. The **114.80 MiB** full estimate double-counts inter-model sharing and must not be presented as measured full-resolution allocation.
- Existing 56 package checks and the 388-GLB/661-part strict-source suite pass, preserving normal full-mip validation and fallback. No original GLBs, levels or image references are replaced.
- All 15 historical Game/F2/HS2Editor images and 13 current strict/package lighting views pass within 1/255. Current pairs are under `qa/lighting-images-20261027-111513/`.
- Final Release solution and Debug/Release authoring builds pass with zero warnings/errors. The final BAT is rechecked with the unclipped budget panel and both directions of the full-detail toggle, then closes cleanly. Whitespace validation passes.

Full-game checks retain the original limits (mean <=17 ms, P95 <=21 ms, at most one >33.3 ms, none >100 ms or streaming waits). Torch-off stress passes **16.715/17.753 ms** and traversal passes **16.662/17.378 ms** mean/P95. Torch-on destruction stress **fails twice**: **17.210/22.587 ms** with four >33.3 ms frames, then **16.836/17.708 ms** with two. No run has >100 ms or streaming waits; packaged runs have 30 hits/zero fallbacks. The new mip path is not used by those gameplay runs. Cause is not established; neither passing gallery data nor a future passing repeat erases these failures. Keep production rollout blocked on investigation/acceptance, not on relaxed gates.

The matching normal strict-source torch-on stress passes **16.775/17.631 ms** with zero >33.3 ms frames, exercising the same six-crate/120-fragment, holding and inventory actions. This narrows follow-up to packaged-run/startup/GC scheduling and repeated matched controls; one source pass does not prove the cause of the package failures.

Up to 256 frame records show raw wall interval, existing clamped simulation interval and asset/lighting/input readiness; totals retain clamped-away time beyond that record limit. The simulation clamp, physics stepping, loading overlay duration and first-playable definition are unchanged.

One clean sequential, uncontrolled-cache diagnostic (`LoadingTestPackages/F2054EEB70EE2390C40E6239/probes/20261027-104935-026-Package.json`) records **3684 ms** process-to-playable, host-ready **1169 ms**, required resources **2618 ms**, 23 startup frames and four clamps discarding **695 ms**. Host window/device take **756/235 ms**; startup physics/world totals are **955/851 ms**. These identify work to investigate, not an optimized result or an additive critical path. Worker timing overlaps. The previous `104913-144` run overlapped a completing build and is excluded from performance conclusions.

The existing 0.85-second overlay uses clamped game time. Initial physics/JIT/settling and the overlay/readiness sequence need controlled follow-up; do not remove either merely to improve a number. Total-startup improvement and true cold-disk speedup remain unproven. Use the no-build/post-restart workflow in [the loading guide](LOADING_PACKAGE_GUIDE.md).
